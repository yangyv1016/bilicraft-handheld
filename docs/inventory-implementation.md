# 背包与资源包分批实现

## 已确认范围

- 目标 Minecraft Java 1.21.11（协议 774），以 `mc.bilicraft.com` 为目标服。
- 会话页右上角菜单新增背包入口，独立页面展示个人背包、快捷栏、装备和副手。
- 支持移动、交换、合并、按数量拆分、切换快捷栏、穿脱装备、副手交换、确认后丢弃。
- 操作流程为点物品、选择操作、必要时点目标槽位。
- 服务器资源包提示下载并缓存，图标以目标服实际资源包验收；无法渲染时保留名称和占位图。
- 聊天、物品名称和描述共用资源包字形渲染。本轮不增加表情选择器。
- 点击带悬停详情的文字打开说明；普通文字点击复制整条消息，整条消息支持长按复制。
- 聊天中的物品是只读展示快照，不是可操作的背包槽位。

## 第三、四批实现与验收（2026-09-24）

- 协议 774 使用随 APK 固定的 Slot schema 解析组件，结合原版默认组件与 configuration 注册表还原名称、附魔、耐久和装备规则。数据由 `scripts/update-inventory-data.py` 生成，来源及校验值记在 `assets/minecraft/inventory-774/sources.json`。未知组件直接报错，不猜长度跳过；背包错误不终止聊天连接。
- 独立背包页展示主背包、快捷栏、装备、副手及光标物品，支持移动、交换、合并、按数量拆分、快捷栏选择、穿脱装备、副手交换、确认后单个或整组丢弃。死亡、其他容器、旧快照和未完成同步状态阻止操作。

## 第五批：服务器菜单（2026-09-24）

收到 774 Open Screen 时，读取窗口类型与 NBT 标题并自动打开服务器菜单；复用资源包字形、图标和物品详情。支持 9×1 至 9×6、3×3 发射器/投掷器、漏斗、潜影盒布局，附带个人背包及快捷栏。类型编号对照官方 1.21.11 服务端 MenuType 注册顺序核验，其他类型显示未适配提示并允许关闭。

点击格子先看详情，随后明确选择“左键点击”或“右键点击”，分别发送 button 0/1 的单次 PICKUP。插件可以把格子当功能按钮，因此不使用个人背包的多步移动计划，也不根据本地预测自动追加点击。等待完整快照或服务器替换/关闭窗口后解除等待；5 秒超时停止且不重发。关闭/替换窗口后的迟到数据被忽略，新窗口有独立 generation，旧详情不能操作新窗口。菜单末尾 36 个玩家槽位同步回个人背包，操作期间避免重复发送。

返回按钮向服务器发送关闭窗口包；光标持有物品时先确认，由服务器处理归还（背包满时可能掉落）。这一出口也用于同步失败后的退出恢复，不会把用户锁在无法操作的菜单里。服务器主动关闭时自动退出页面。

## 第六批：聊天命令链接（2026-09-27）

补齐聊天点击事件到会话发送/输入框的链路。支持旧 `clickEvent.value` 与新 `click_event.command` 的 `run_command`、`suggest_command`；父组件及组件数组继承、extra 兄弟隔离、传统颜色切片均保留事件。新格式允许无 `/`，归一化后仍走命令通道；建议命令原样填入输入框，不发送。未知动作、错误类型与非法聊天字符不变成可执行命令。格式依据：[Mojang 1.21.5 Click Events 变更](https://feedback.minecraft.net/hc/en-us/articles/35298208390797-Minecraft-Java-Edition-1-21-5-Spring-to-Life)。

普通 Compose 文字与资源包 TextView 字形均按文字范围命中点击事件，旁边的普通文字继续复制，整条长按复制。只有点击命令时直接执行；同一片段同时携带悬停详情时，保留点击查看详情，并在弹窗加入“执行点击命令”或“填入聊天框”。执行仅允许当前已连接的对应服务器，发送命令不改写已有聊天草稿。物品名称、描述中的文本展示不自动启用命令执行。

## 第七批：玩家头颅（2026-09-27）

补齐 `minecraft:player_head` 专用物品渲染，背包、服务器菜单和聊天物品详情共用。此前普通模型支持没有覆盖这个专用渲染器，导致服务器大量使用的头像和自定义头颅仍显示占位图；本批修复这一遗漏。

- 统一网络 Slot 与聊天 NBT 的 profile 数据，保留 UUID 整数数组、玩家名、textures 属性及皮肤覆盖。按静态/动态 profile 规则解析，支持内嵌 Base64 皮肤属性、玩家名或 UUID 查询；没有自定义皮肤时按 UUID 选择原版默认皮肤。

## 后续实现约束

- 资源包继续以真实下载/解析结果回报状态；新增 provider 或模型规则时，用目标服素材补充验收，不把静态支持扩大描述为完整游戏渲染。
- 若以后加入 774 客户端预测，HashedSlot 的组件 hash 必须使用结构化 HashOps CRC32C，不能用原始网络字节 CRC；当前采用上文的不预测完整同步策略。
- 不用猜测的组件长度跳过未知 Slot；不确定的操作不能盲目重发，丢弃尤其如此。
- 背包操作先以本地测试服务器/测试物品验收，再检查目标服兼容；不在正式背包上做破坏性测试。
- 每次重新安装后重新查询 MuMu 的逻辑 display ID 与物理截图 ID。截图失败时不能沿用设备上的旧图片作为验收证据。
